# 搜索增强方案：让每个角色拥有“联网小助手”（gemini-2.5-flash-search）

## 背景与目标
- 现状：各专业角色（快讯猎手、基本面专家、技术分析师、情绪分析师、风控经理）主要依赖本地/缓存/统一接口数据。在无网或数据源受限时可用，但缺少“实时联网检索”的能力。
- 目标：为每个角色注入一个可调用的“联网小助手”（Search Assistant），由多模型管理器调度 `gemini-2.5-flash-search`（Flash + 联网搜索）模型获取实时信息，并将检索结果回填到角色的分析上下文中。

## 方案概览
- 核心思想：保持现有“角色 → MultiModelManager.execute_task()”主流程不变，在每个角色分析前增加一个可选“搜索阶段”。
- 搜索阶段职责：
  1) 将问题域（股票/日期/关注要点）转为检索 query。
  2) 使用 `gemini-2.5-flash-search` 联网检索与摘要，产出结构化“外部证据”。
  3) 把“外部证据”插入角色提示词上下文（context_data.external_sources）。
- 触发策略：
  - 默认开启：快讯猎手（NewsHunter）、情绪分析师（SentimentAnalyst）。
  - 可按角色、任务类型或上下文开关（如 `context["enable_web_search"] = true`）。
  - DEMO_MODE 或无网时自动跳过，回退到现有离线数据管道。

## 模型与服务
- 服务文档：`api文档/Gemini-API-服务介绍.md`
- 关键信息（OpenAI 兼容）：
  - Base URL: `https://jimiround-latest.onrender.com/v1`
  - API Key: `166067743`
  - 联网模型：`gemini-2.5-flash-search`、`gemini-2.5-pro-search`
- 优先选择：`gemini-2.5-flash-search`（快速 + 联网），作为“Search Assistant”默认模型。

## 配置改动（multi_model_config.yaml）
- providers.gemini_api：启用并设置 base_url（如需覆盖默认值）

```yaml
providers:
  gemini_api:
    enabled: true
    base_url: "https://jimiround-latest.onrender.com/v1"
    default_model: "gemini-2.5-flash-search"  # 搜索默认走 flash-search
    timeout: 90
    max_retries: 2
    priority: 1
    pool_type: "deep_reasoning"
```

- task_bindings：新增 `web_search`

```yaml
task_bindings:
  web_search:
    allow_models: ["gemini-2.5-flash-search", "gemini-2.5-pro-search"]
    prefer_models: ["gemini-2.5-flash-search"]
```

- agent_bindings：为相关角色绑定搜索首选（可选）

```yaml
agent_bindings:
  news_hunter:
    allow_models: ["gemini-2.5-flash-search", "deepseek-ai/DeepSeek-V3"]
    prefer_models: ["gemini-2.5-flash-search"]
  sentiment_analyst:
    allow_models: ["gemini-2.5-flash-search", "zai-org/GLM-4.5"]
    prefer_models: ["gemini-2.5-flash-search"]
```

## 代码改动点（建议）
> 注：以下为最小侵入的集成方式；不破坏现有数据管道，搜索作为“增强”而非“替代”。

1) 新增 SearchAssistant（工具层）
- 路径建议：`tradingagents/tools/search_assistant.py`
- 作用：封装一个便捷函数，内部调用 `multi_model_manager.execute_task()`，`task_type="web_search"`，`complexity="low/medium"`，`requires_speed=true`。
- 伪代码：

```python
class SearchAssistant:
    def __init__(self, mm):
        self.mm = mm

    def query(self, agent_role: str, query: str, context: dict | None = None) -> str:
        ctx = {"session_id": context.get("session_id") if context else None,
               "model_params": {"temperature": 0.2, "max_tokens": 1024}}
        result = self.mm.execute_task(
            agent_role=f"{agent_role}_search",
            task_prompt=query,
            task_type="web_search",
            complexity_level="low",
            context=ctx,
        )
        return result.result if result and result.success else ""
```

2) 在协作编排处插入搜索阶段
- 建议位置：`tradingagents/graph/multi_model_extension.py` 的 `_prepare_agent_input()` 中，在构造各角色输入时：
  - 根据角色 + 上下文判断是否需要联网搜索。
  - 以“角色专属 query 模板”发起一次 `SearchAssistant.query()`。
  - 将结果注入 `base_input["external_sources"] = {...}`，并在最终提示词中拼接。
- 已有改动（本次已完成的数据填充）与该步骤兼容：若搜索失败，继续使用现有离线/统一数据兜底。

3) 可选：为 `BaseSpecializedAgent` 增加开关与 Hook
- 在 `analyze()` 之前调用 `self.fetch_realtime_context()`（默认空实现），各子类可复写或通过配置启用。
- 避免直接在基类中引入强耦合，保持 SearchAssistant 的注入式调用。

## 角色级搜索提示词模板（示例）
- NewsHunter：
  - Query: `"{symbol} 最近7天 重大新闻 OR 快讯 OR 公告 影响 股价 的 动态 来源:权威媒体"`
  - 目标：提取时间、事件、主体、影响方向、可信度；返回项目化要点。
- SentimentAnalyst：
  - Query: `"{symbol} 舆情 情绪 讨论 热度 关键词 近7天 site:微博 OR 百度贴吧 OR 机构快评"`
  - 目标：给出情绪分布、极端值、驱动因子、样例引用。
- TechnicalAnalyst：
  - Query: `"{symbol} 技术面 关键位 位于 近期 资金流向 关键催化 事件"`
  - 目标：辅助识别事件驱动与价位联动（不替代行情数据）。
- FundamentalExpert：
  - Query: `"{symbol} 基本面 业绩 指引 财报 摘要 机构观点 近90天"`
  - 目标：提炼财报要点与一致预期变化。
- RiskManager：
  - Query: `"{symbol} 风险 监管 诉讼 信用 供应链 中断 负面事件 近90天"`
  - 目标：形成风险清单与概率/影响度。

> 输出格式建议：要求模型返回“要点列表 + 关键证据链接（如可用）+ 时间戳”。

## 回退与演示模式
- DEMO_MODE=true：跳过联网搜索，沿用现有离线/演示数据；保持稳定可演示。
- 网络/鉴权异常：记录告警，不影响主流程；`external_sources` 为空时继续只用本地/统一数据。

## 成本与速率控制
- 成本：`flash-search` 成本较低，建议设置 `max_cost_per_task`（见 `agent_bindings`）。
- 速率：每个角色最多 1~2 次搜索；集中在 “news_hunter / sentiment_analyst”。
- 缓存：可将搜索摘要按（symbol, date, role）做短期缓存（如 2~6 小时）。

## 验证步骤
1. 配置 `.env`：
   - `GEMINI_API_COMPAT_BASE_URL`、`GEMINI_API_COMPAT_API_KEY` 生效。
2. 更新 `config/multi_model_config.yaml`（providers、task_bindings、agent_bindings）。
3. 运行多模型协作（常规或演示模式）：
   - `python main_multi_model.py 000625 2025-08-17 sequential --agents news_hunter sentiment_analyst fundamental_expert risk_manager`
4. 在日志中核对：角色在构造输入时出现 “web_search” 调度；最终输出包含 `external_sources` 要点。
